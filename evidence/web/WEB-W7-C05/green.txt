--- repo seeding note (why not a bind mount) ---
This Docker Desktop does not mount Windows host paths (any -v/--mount of a
host path hangs container start — verified). The checkout is streamed as a
tar into the `repo-src` named volume via `docker compose exec -T reposync
sh -c 'tar -xf - -C /repo'` plus a `.rxy-sync-done` marker file. Ordering is
marker-file based (.rxy-sync-done -> .migrate-done in boot-state vol ->
index.html in web-dist), NOT `depends_on: service_completed_successfully`,
so `up -d` returns immediately and the seed happens after — no deadlock.
On a Linux host the same stack could use bind mounts, but the tar path is
what was exercised here and works everywhere; runbook documents it.
