# Grok 4.5 · 前端辅助手册（多模态场景）

> **这份文档不是计划，是纪律。** 它约束的是"辅助模型怎么干活"。
> **模型分工权威**：[`MODEL-ASSIGNMENT.md`](./MODEL-ASSIGNMENT.md) —— **Composer 主写全部代码；Grok 只在写前端用到多模态（视觉）时才介入。**
>
> **适用范围**：RxyCode / LinkAgent 前端工作里**需要"看"的环节**——渲染截图核对、视觉 bug 定位、图片类 UI（粘贴/预览）、照着设计稿/竞品截图实现。
> **不写**：后端代码（Python、`core/`、`appserver/`、`src/linkagent/**/*.py`）；没有多模态环节的前端卡本体（那是 Composer 的主写范围）。
> **副业**：前端窗口空闲时，仍可查外部资料（旧职责保留），查到的内容要落进文档。
> **创建**：2026-08-01 · **修订**：2026-08-01（改为辅助定位）

---

## §1 为什么需要这份文档

选你（Grok 4.5）不是因为"前端归你"，是因为你**多模态**——前端卡里凡是要"看"的环节，你比纯文本模型强。你的强项和翻车点都由此而来：

| 它很强的 | 它会翻车的 |
|---|---|
| **看**：渲染截图找视觉 bug、布局/对齐/层级问题 | **顺手改协议语义**（前端发明字段） |
| **对比**：改动前后截图、设计稿 vs 实现 | 没 schema 时手写"临时类型"然后永远留下 |
| UI 结构、交互、视觉层次（看图说话） | 大范围重写 Electron 壳 |
| 图片类 UI：粘贴/预览/附件选择的实现 | 把调研结论直接写进业务逻辑而不落文档 |
| 查官方文档、竞品 UI 做法 | 为了联调去改 Python / schema |

**推论：你只做"看得到"的环节。** 前端卡的本体由 Composer 主写；卡里标注了「多模态环节」的段落才是你的活。视觉可以有限发挥，契约决策零发挥。

## §2 八条硬规则

> 违反任何一条，这部分产出都要打回重做。

### G1 · 一次只做一个多模态环节

做完一个环节，交给 Composer 收口（合并/commit），再开下一个。不要攒着。

### G2 · 不读整份施工文档，只读那张卡的多模态环节 + 协议契约

正确姿势：
```
读 MODEL-ASSIGNMENT §0 → 读本手册 §2 → 读你要辅助的那张卡的「多模态环节」小节 → 开工
```

错误姿势：
```
通读 L0–L10 → 上下文塞满 → 开始"综合考虑" UI 和语义 → 越界改后端或改卡本体
```

不要通读。后端语义不归你，卡本体不归你。

### G3 · 类型从 schema 生成，禁止手写平行类型

- `generated/types.ts` **只允许生成，不许手改**
- 上游 `schema.json` 未合并 → **停工**，不要先写 `any` / 本地 interface 顶上
- CI 有生成物新鲜度检查的，合并前必须绿

### G4 · 只碰白名单文件（且只在标注的环节里）

卡里"涉及文件"表外一律不改；表内文件也**只动你那个环节涉及的片段**：

- ❌ `src/linkagent/**/*.py` · `core/` · `appserver/` · `api_server.py`
- ❌ 为了让 UI 好看去改事件载荷形状
- ❌ 顺手"顺便修"同一文件里不属于本环节的代码

### G5 · 产出并入 Composer 的卡，不单独开 commit

辅助产出的 commit 由 Composer 那张卡收口。你本地可以 commit，但推送/合并动作归 Composer；commit message 里注明哪个环节是辅助产出。**前端没有你的独立分支。**

### G6 · 视觉验收是硬动作，不是可选动作

每个你参与的前端环节，交付前必须**用你自己的视觉能力截屏自检**：

```
1. 启动卡里给的应用/组件（dev server / 烟测命令）
2. 截屏：正常态 + 空态 + 加载态 + 错误态（卡里有要求的才做）
3. 自己看图核对：布局、对齐、溢出、层级、文案是否与卡里描述一致
4. 发现问题的先自己修，修不了或不确定 → 贴图 + G8 报告
```

- **你看到什么就是什么**：不能靠"逻辑上应该没问题"交差，必须看过图。
- 联调类问题（依赖后端行为）**不是视觉验收**——那是 Composer 的联调卡。
- 验收命令（`npx tsc --noEmit` / `npx vitest run`）同样全绿，截图自检是**额外的**一层。

### G7 · 不碰后端，不发明协议

**硬边界。**

| 可以 | 不可以 |
|---|---|
| 调用已有 JSON-RPC 方法 | 新增 `eko/update` 之类写方法（协议禁止） |
| 渲染 `event/eko_*` | 改事件字段含义 |
| 从合并 schema 生成类型 | 手抄一份"差不多"的类型 |
| 做卡里标注的视觉/图片环节 | 去做没有多模态环节的前端卡（Composer 的） |

联调失败：**视觉问题你修；契约/后端问题开 Composer 卡**。不要跨界一把梭。

### G8 · 卡住了就停下来问，不要发挥

| 情况 | 为什么必须停 |
|---|---|
| 图截不出来 / 应用起不来 | 环境不对，继续做只会浪费 |
| 找不到卡里说的多模态环节 | 你可能在辅助一张不需要你的卡，确认一下 |
| 需要碰 Python / `core/` / `appserver/` | 后端是 Composer 的，跨界等于撕毁分工 |
| 发现协议里没有的写方法（如 `eko/update`） | 要么你记错了契约，要么产品决策被破坏，必须先停 |
| 视觉自检发现的问题修了 3 次没好 | 你的假设错了，继续试只会越改越乱 |

**报告格式**：
```
STOP：<一句话说清卡在哪>
我做到了：<已完成的部分>
我需要：<具体需要什么决定或信息>
我没有改：<确认没有越界>
```

停下来问**不算失败**，猜错了继续往下做才算。

## §3 前端卡长什么样（你能辅助的部分）

前端卡由 Composer 主写，结构见 [`COMPOSER-2.5-PLAYBOOK.md`](./COMPOSER-2.5-PLAYBOOK.md) §3。你只关心卡里的这个字段：

```markdown
**多模态环节**（Grok 辅助，规则 G6）
- 环节 1：视觉验收——完成后截屏核对渲染（正常/空/加载/错误态）
- 环节 2：图片粘贴区实现 + 自测（贴图、预览、清除）
```

**没有这个字段的前端卡，不是你的卡。** 有的话，你的产出边界就是卡里列出的那些环节。

Composer 委托你的请求长这样（见 COMPOSER §4），确认三件事再开工：

1. 环节边界（哪几件事是你的）
2. 交付物（代码片段 / 截图 / 问题清单）
3. 验收命令（含怎么起 dev server 截屏）

> 与后端卡唯一的区别：**类型从 schema 生成（G3）**，所以卡里"涉及文件"通常包含 `generated/types.ts`——它是生成物，不在"手改"范围。

## §4 和 Composer 的协作（辅助侧）

| Composer（主写） | 你（Grok） |
|---|---|
| 写前端卡本体、合并 `schema.json`、生成 TS | 只做卡里标注的多模态环节 |
| appserver / 审批 broker | 弹审批 UI、回贴 decision 后**截图核对视觉** |
| 前端联调、契约问题 | 视觉 bug 定位（贴图指出哪不对） |
| 收口你的产出（commit / PR） | 产出交回，不另开分支 |

**产品决策硬约束（LinkAgent）**：用户不能通过 UI 直接编辑 EKO。协议层没有写方法；你也**不许**做"本地假写入"或隐藏调试按钮绕过——不管视觉上多合理。

交接点规则详见 [`MODEL-ASSIGNMENT.md`](./MODEL-ASSIGNMENT.md) §1。

## §5 副业：查外部资料

前端窗口空闲时（Phase 0/1、LinkAgent L0–L8 期间）可以查资料，规则不变：

```
查 <具体的技术问题>：
1. <子问题 1>
2. <子问题 2>
每条给出文档原文和 URL。不要给推测，查不到就说查不到。
```

**最后一句很重要。** 你（Grok）在查不到时倾向于给一个听起来对的答案，必须显式禁止。

查回来的东西**落进施工文档或卡注释**，不要只留在对话里——下一个会话（无论 Composer 还是 Grok）都看不到。

**空闲 ≠ 可以接管前端。** 没有多模态环节可做时宁可空着或查资料，也不要去写卡本体或 Python。

## §7 常见失败模式与预防

| 失败模式 | 长什么样 | 防护 |
|---|---|---|
| **手写临时类型** | `desktop/` 里出现与 schema 平行的 interface | G3 |
| **发明写接口** | UI 调用不存在的 `eko/update` | G7 + APPENDIX-C |
| **为联调改后端** | diff 里出现 `.py` | G4 / G7 |
| **越界接管卡本体** | 没有多模态环节的卡也"顺手"做了 | G4 / G7 + MODEL-ASSIGNMENT §0 |
| **靠逻辑交差** | 没截屏就说"应该没问题" | G6 |
| **静默扩大范围** | 顺手改了同一文件里无关片段 | G4 + `git diff --stat` |
| **空闲时写后端** | Phase 1 期间改了 `core/` | MODEL-ASSIGNMENT §3 |

### Review 清单

```powershell
git diff --stat                 # 有没有 .py？有没有环节外的文件？
git diff -- '*generated*'       # 生成物是否被手改？
npx tsc --noEmit                # 类型过了吗？
npx vitest run                  # 单测过了吗？
# 视觉：截图核对完成，问题已贴图或已修（G6）
```
