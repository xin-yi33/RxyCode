# 每日执行检查清单（Daily Checklist）

这是一个可打印的每日清单，帮助团队成员和项目经理追踪每天必须完成的事项。

---

## 📋 项目经理每日清单

### 早上（9:00-10:30）

```markdown
时间：9:00
- [ ] 查看GitHub通知和新的Issue
- [ ] 查看CI/CD状态（有无失败的构建）
- [ ] 查看Slack未读消息
- [ ] 准备站会议程

时间：10:00-10:15
- [ ] 主持每日站会
  - [ ] 每个人报告昨天/今天/阻碍
  - [ ] 记录行动项
  - [ ] 识别风险

时间：10:15-10:30
- [ ] 更新项目看板
- [ ] 跟进昨天的行动项
- [ ] 处理紧急问题
```

### 下午（随时）

```markdown
- [ ] 审查待批准的PR（至少查看标题和描述）
- [ ] 回复团队成员的问题
- [ ] 更新进度追踪表
- [ ] 如有阻碍，立即协调解决
```

### 晚上（下班前）

```markdown
时间：17:30
- [ ] 检查今天的提交记录
- [ ] 检查今天的PR合并情况
- [ ] 记录今天的重要事件
- [ ] 准备明天的议题（如有）
- [ ] 发送每日进度快报（可选）
```

## 💻 开发人员每日清单

### 早上（9:00-10:00）

```markdown
时间：9:00
- [ ] 查看GitHub通知
- [ ] 查看分配给我的Issue
- [ ] 查看我的PR的Review反馈
- [ ] git pull origin main（更新代码）
- [ ] 准备站会发言（昨天/今天/阻碍）

时间：10:00-10:15
- [ ] 参加每日站会
```

### 上午编码时段（10:15-12:00）

```markdown
- [ ] 从站会行动项中选择今天的任务
- [ ] 创建或切换到功能分支
- [ ] 编写代码
- [ ] 编写测试（TDD方式）
- [ ] 本地运行测试确保通过
```

### 下午编码时段（14:00-17:30）

```markdown
- [ ] 继续编码和测试
- [ ] 至少每2小时提交一次（小步提交）
- [ ] 如果任务完成：
  - [ ] 运行完整测试套件
  - [ ] 运行代码检查（ruff/mypy）
  - [ ] git push并创建PR
  - [ ] 在PR中详细描述变更
  - [ ] 请求Code Review
```

### 晚上（下班前）

```markdown
时间：17:30
- [ ] 提交今天的所有工作（即使未完成）
- [ ] 更新Jira/GitHub任务状态
- [ ] 回复今天收到的Code Review评论（如有）
- [ ] 记录明天要做的事情
```

## 🔍 代码审查者每日清单

如果你被指定审查PR：

```markdown
收到PR通知后（24小时内）：
- [ ] 阅读PR描述和关联的Issue
- [ ] 检出分支到本地：git fetch && git checkout <branch>
- [ ] 运行测试：pytest
- [ ] 运行代码检查：ruff check . && mypy .
- [ ] 阅读代码变更
- [ ] 检查以下方面：
  - [ ] 功能正确性
  - [ ] 代码清晰度
  - [ ] 测试充分性
  - [ ] 文档更新
  - [ ] 性能考虑
  - [ ] 安全问题
- [ ] 留下评论或批准
- [ ] 如果有问题，清楚说明需要改进的地方
```

## 🚨 异常情况处理清单

### 如果CI失败

```markdown
- [ ] 立即通知相关开发者（Slack @他们）
- [ ] 检查是什么原因（测试失败/构建失败/代码检查失败）
- [ ] 如果阻塞主分支：
  - [ ] 标记为P0优先级
  - [ ] 要求立即修复（2小时内）
  - [ ] 如果2小时未修复，考虑revert PR
- [ ] 记录到问题追踪系统
```

### 如果有团队成员报告阻碍

```markdown
- [ ] 立即响应（不超过30分钟）
- [ ] 了解详细情况
- [ ] 评估影响范围
- [ ] 如果能立即解决：协助解决
- [ ] 如果不能立即解决：
  - [ ] 分配替代任务
  - [ ] 升级到相关负责人
  - [ ] 记录到风险追踪
  - [ ] 在下次站会讨论
```

### 如果发现进度落后

```markdown
- [ ] 分析原因（技术/人员/需求）
- [ ] 与架构师讨论
- [ ] 评估影响（是否影响里程碑）
- [ ] 制定应对方案：
  - [ ] 增加人力？
  - [ ] 减少范围？
  - [ ] 延长时间？
- [ ] 向管理层报告（如需要）
- [ ] 更新项目计划
```
