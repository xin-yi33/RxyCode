# RxyCode Web 用户指南

版本 1.4.4。协议版本 1.1.0。

本指南没有截图。编写时没有采集屏幕。

## 选择运行位置

打开 `/onboarding`。页面始终显示当前权限和执行目标。

- 本地：目标 `local`。登录前权限为空，状态 `needs-login`；用本机口令登录后，权限仍为空，状态变为 `waiting_for_local_confirmation`，因为 Full 权限必须在本机界面上确认授予，浏览器只能看到镜像状态，看不到 `full` 本身。本机回环，不需要 GitHub 账户。
- 云端：目标 `cloud`。授权前权限为空，状态 `needs-github`；完成 GitHub 授权后权限为 `cloud`，状态 `ready`。未授权的回调会被拒绝。只完成本机登录而没有 GitHub 授权时，云端仍显示 `needs-github`。
- 远程：权限为空，目标 `remote`，状态 `waiting_for_local_confirmation`。没有已配对且在线的本机设备时，云端会以 404 拒绝 Remote Full 调用，也不会写入 `remote-full.txt`。

断线时页面显示「无法连接」，点「重试」会重新读取当前身份。

## 第一次安装

1. 准备本机 Postgres，并让网页进程使用它的连接串。
2. 产物下载需要对象存储。已有的 MinIO 在 `127.0.0.1:59000` 时直接用。没有的话只启动名为 `rxy-w6c06-minio` 的容器，端口 `127.0.0.1:59010`。不要删掉别的容器。
3. 本地模式使用一份共享的本机账户。退出登录不会删掉这个账户。
4. 云端导入只接受 `https://github.com/<owner>/<repo>` 和 40 位十六进制修订号。其他地址会在克隆之前被拒绝，原因记为 blocked。这一步没有启动 gVisor，也没有克隆 GitHub 仓库。

## 一次任务怎么结束

登录后创建项目和会话，再创建一次 Run。验收用的测试是工作目录里单独的 `test_release_marker.py`，由真实的 `python -m pytest` 跑完。输出存成产物 `pytest.txt`，再用签名链接下载。链接有效期不超过 15 分钟。

关掉页面之后，用同一条 run 再读一次事件。两次读到的事件类型必须一致，其中包含 `artifact.created`，才算恢复对照通过。

## 排错

- 登录返回 403：检查本机口令、`Origin` 是否在允许列表，以及 `rxy_csrf` cookie 是否和 `x-csrf-token` 一致。
- 导入被拒绝：地址不是 GitHub 仓库，或修订号不是 40 位十六进制。这是拒绝，不是导入成功。
- 下载失败：签名过期、租户不匹配，或对象存储没有启动。
- 远程没有执行：设备不在注册表里，或者没有活的 socket。先在本机确认设备，再谈执行。
